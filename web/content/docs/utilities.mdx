These commands are in **GroomLab > Utilities**. They act on the active groom (Find Missing Files:
the selected grooms), and each is one undo step.

## Conversions

| Command | Result |
| --- | --- |
| **Guides to Curves** | One NURBS curve per guide, tagged with its guide ID. |
| **Curves to Guides...** | Tagged curves update their own guide in place; any other curve becomes a new guide. |
| **Strands to Curves...** | The evaluated strands as plain Maya curves (20,000 by default), with their attributes. |
| **Strands to Mesh...** | A snapshot of the strands as one mesh of tubes or ribbons, with UVs, for exporting. For a mesh that follows the animation, see [Strands as a mesh](#strands-as-a-mesh). |
| **Bake Node to Guides...** | The groom's output, or any node's strands or guides, converted to brushable guides. To keep them procedural instead, use a ToGuides followed by a Sculpt node ([Node graph](/docs/node-graph#other-main-nodes)). |

To edit guides with Maya tools: **Guides to Curves**, edit the curves (CVs, lattices, a sculpt
deformer), then **Curves to Guides...**.

## Delete All Flow Arrows

Removes every flow arrow and sink from the active groom in one undo step, and reports how many
were removed. The arrows are kept on the groom (laid with the **Flow** tool), not in the Flow node.
The Flow tool's card counts them and has the same command as **Clear All**. See
[Short hair without guides](/docs/guides-and-brushes#short-hair-without-guides).

## Strands as a mesh

**Strands to Mesh...** makes a static mesh of the current frame: a tube (`Tube sides` around, the
tip closed) or a flat ribbon along each strand, as wide as the strand times `Width scale`. UVs
run across the strand (u) and from root (v 0) to tip (v 1); **Per-strand UVs** adds a second UV
set, `strandUVs`, with each strand in its own cell of a grid. Beyond **At most** strands, the
strands are thinned by strand ID, the same ones a lower density keeps.

For a mesh that follows the animation, add a **StrandMesh** node in the Graph Editor. The groom
draws its mesh in the viewport at once, in place of the strands (**Show mesh** in the node's
panel, the groom's `displayStrandMesh`, switches back to the strands). The mesh shows the strands
the node receives, so its position decides what it includes: after a Simulate's Interpolate it
moves with the simulation, and before a Noise it leaves the frizz out. It follows the scalp (with
Follow scalp on), Simulate (live or baked), keyed params and graph edits. Its vertices and faces
stay the same from frame to frame; only the points move. Changing the node's density, strand
count, style or sides rebuilds it. Each StrandMesh node passes its strands on unchanged, and all
of them share one mesh.

To cache the animated mesh, click **Mesh in Scene** in the node's panel: it makes a Maya mesh
connected to the groom's `outStrandMesh` (or selects the one already there). Export it with
Maya's Alembic export (**Cache > Alembic Cache > Export Selection to Alembic**, or
`AbcExport -frameRange 1 120 -uvWrite -root |hair_strandMesh -file hair.abc`); it is written as
one deforming mesh. While that mesh exists, it shows the mesh instead of the groom.

From Python:

```python
import groomlab
from groomlab import utils
utils.strands_to_mesh(groom, sides=4, max_strands=20000)                # a snapshot
node = groomlab.add_strand_mesh(groom, after="interpolate", style="ribbon")  # live, drawn by the groom
mesh = groomlab.strand_mesh_shape(groom)                                # Mesh in Scene
```

<Callout type="warn">
Tube meshes are heavy: 4 sides make about 4 vertices per strand point, so 20,000 strands of 16
points are 1.3 million vertices. A mesh of the full groom is meant for renderers and tools without
curve support, or for a few hero strands. Game engines usually use guide-driven strands (Unreal
grooms) or hair cards instead ([Game export](/docs/game-export)).
</Callout>

## Start from existing curves

- **Maya curves:** select the scalp and the curves, then **Create Groom from Selection**. Or add
  them later with **From Curves** under Guide groups & edits.
- **Alembic curves** (from Houdini or XGen): **GroomLab > Import > Alembic Curves...** (also
  under **Import** in the Groom Tools' **Output** section), or
  `groomlab.import_guides_from_alembic(groom, path)`. In the app and Blender, an **ImportCurves**
  node reads an Alembic file's curves.

## Transfer to a new scalp

To move a groom to a new sculpt, a retopologized head or another character, open **Utilities >
Transfer Groom to Scalp...** (or **Transfer...** in the Groom Tools' **Output** section; in the
app, **Tools > Transfer Groom to Scalp...**). The groom's scalp is shown on the left and the mesh picked in **New
scalp** on the right, each in its own view (Alt moves the camera).

Pick a **Method**:

| Method | For |
| --- | --- |
| Closest point | The new mesh where the old one was (a new sculpt in place). |
| Fit bounds | The same shape elsewhere or of another size. |
| Markers: align | The same head moved, turned or scaled. 3 marker pairs or more. |
| Markers: warp | Another character: a head of other proportions, mapped feature to feature. 4 pairs or more. |
| UV | Both meshes share their UV layout (a retopology). Exact, no markers. |

**Markers** work as in Wrap: click a point on each mesh. Pair N is the Nth point on the left and
the Nth on the right, in any click order (five on the old head, then five on the new, or
alternating).

- A point without its partner yet shows as a hollow ring; it fills in once paired.
- **Ctrl+click** deletes a point and its partner, and both sides renumber.
- **Drag** a point to slide it; hover one to light its partner.
- **Ctrl+Z / Ctrl+Y** in the window undo and redo marker edits; **Symmetry** mirrors each new
  point across the mesh's middle.
- Ears, temples, crown, nape and brow make good pairs; six to ten are plenty for a warp.
- The pairs are saved with the groom (and in `.groom` files), so a later transfer reuses them.

Guides, parts, flow arrows and painted maps are all transferred through the mapping; each guide is
rotated and scaled with the surface around its root (**Keep guide lengths** disables the
scaling). **Copy mesh color sets** also copies Maya color sets. While it transfers, the window shows
a wait cursor, greys out its buttons and says what it is doing. One **Ctrl+Z** in Maya undoes the
whole transfer, and the window updates accordingly.

By default the groom keeps the size it shows: on a bigger head the hair keeps its lengths and the
same density covers more skin. **Fit groom to the new scalp's size** treats the new scalp as the
old one resized instead: the groom's scale grows with the scalp's area
([Scaling a groom](/docs/guides-and-brushes#scaling-a-groom)), so lengths, widths and clumps
follow, the strand count stays the same and the guides scale about their roots (the mapping only
turns them). In Python: `groomlab.transfer_groom(groom, "bigHead", fit_size=True)`.

Without the window: click **Pick** on the Scalp row of the groom's Attribute Editor, or choose the
mesh in the Scalp node's **Mesh** field (closest point method).

```python
groomlab.transfer_groom(groom, "newHead")                                  # closest point
groomlab.transfer_groom(groom, "bigCat", method="bounds")                  # another size or place
groomlab.transfer_groom(groom, "otherHead", method="markersWarp",
                        markers=[("head.vtx[12]", "otherHead.vtx[40]"), ...])
```

## Copy Graph to Other Grooms

Pin (or select first) the source groom, select the target grooms and choose **Copy Graph to Other
Grooms...**. Choose whether to keep or replace their guides; **Copy painted maps** also copies the
maps the graph reads.

## Find Missing Files

After a failed copy or a moved project, **Find Missing Files...** relinks the files the selected
grooms (or every groom) cannot find: texture maps, images and Alembic files referenced in the
graph, guide caches and groom files. Pick a folder; it searches it and its subfolders for files of
the same name.

- Names compare without case on Windows.
- When several files share a name, the one whose folders best match the stored path is used. If
  none matches, the file is reported as ambiguous and not relinked.
- The Script Editor lists every file relinked, ambiguous or still missing. It is one undo step.

```python
groomlab.missing_files(groom)                         # what is missing, by kind
groomlab.find_missing_files([groom], "D:/recovered")  # relinked, still_missing, ambiguous
```

## Collect Files

**Collect Files** copies every file the selected grooms (or every groom) use from outside the
scene's folder into its groomlab folder (masks, caches, cards and exports, under each groom's
name) and points the grooms at the copies, kept relative. The scene's folder then holds
everything, ready for Archive Scene, a zip or another machine. Files already inside stay where
they are; a missing file is listed in the Script Editor (Find Missing Files relinks it). Save the
scene first. It is one undo step (the copies stay).

```python
groomlab.collect_files()   # copied, missing, inside
```

## Files in a pipeline

Every file a groom uses shows in Maya's **File Path Editor** (Windows > General Editors) under
**GroomLab**: its texture maps, the images and Alembic files its graph reads, its guide cache,
Simulate bakes, card bake and the groom file it renders from. Repath them there or with Replace
String and the groom follows, its paths kept relative to the scene.

Farm submitters, publish and archive scripts can collect them too (Maya's own Archive Scene only
sees Maya's node types):

```python
for groom in cmds.ls(type="groomLabShape"):
    for f in groomlab.file_dependencies(groom):      # kind, key, path, resolved, exists
        print(f["resolved"])
groomlab.repath_file(groom, "map", "density", "/publish/hair/density.png")
```

Each file is a small `groomLabFile` node connected to its groom (`ls -type groomLabFile`, the path
in its `fileName`), kept in step as the groom changes and before every save.

## Colliders

Click **Pick** on the Collider row of the Attribute Editor's **Inputs**, then click the body,
collar or hat in the viewport or the Outliner (`groomlab.add_collider(groom, mesh)`). The button
reads **Cancel** while waiting; Esc cancels. GroomLab adds a ColliderMesh node and a Collide node
before the output. Animated collision meshes are evaluated per frame in the viewport, renders and
exports.

In the Graph Editor, a **Scalp** or **ColliderMesh** node's panel has a **Mesh** field: a menu of
the scene's meshes, the same pick button and **Select**. Choosing a mesh there reconnects the
scalp or that collider, as the Attribute Editor does.

## Themes

A theme sets the colors of the Groom Tools, the Graph Editor, GroomLab's windows and the
viewport's guides. Pick one in **GroomLab > Theme**, or **Theme** in the Groom Tools' **More**
menu or the Graph Editor's **Edit** menu. It applies at once and is remembered across sessions.

| Theme | Look |
| --- | --- |
| **Playful** (default) | Charcoal with bright primaries, flat and round. |
| **Charcoal** | Calm neutral greys, an off-white primary button, thin borders, muted color only where it means something. |
| **Polar** | Near-black and monochrome with one indigo accent. |
| **Studio** | Low-key greys with one accent. |

To make your own, choose **Theme > New Theme from Current...** in the Groom Tools or the Graph
Editor: it copies the active theme to a JSON file in your themes folder. Edit its colors, then
**Theme > Reload Theme**. In Python:

```python
from groomlab.ui import theme
path = theme.create_theme("mine", base="charcoal")  # a copy to edit
theme.set_theme("mine")
```

A theme can set only some keys; the rest come from the theme it names in `"extends"` (Playful by
default).
