GroomLab has no chat window of its own. Instead, `groomlab-cli` has an MCP server built in, so
the AI app you already use can drive GroomLab directly. MCP (the
[Model Context Protocol](https://modelcontextprotocol.io)) is an open standard for connecting AI
apps to tools: the app starts a small program on your machine, asks it which tools it has, and
lets its model call them. With GroomLab connected, you can ask for "a curly bob on Nika, a bit
redder", and the agent builds the groom, looks at a preview, adjusts it and saves a `.groom` file
that Maya, the app, Blender and the render procedurals open.

The server runs on your machine and makes no network connections. It reads and writes files only
inside one folder that you choose.

## Where groomlab-cli is

`groomlab-cli` comes in the Maya download, in the `GroomLab\bin` folder of the module. If you
unzipped it to `Documents\GroomLab`, that is:

```text
C:\Users\<you>\Documents\GroomLab\GroomLab\bin\groomlab-cli.exe
```

On Linux it is `GroomLab/bin/groomlab-cli` in the `groomlab-<version>-linux-x86_64.tar.gz`
archive. The standalone app's zip does not include it.

The server is started as `groomlab-cli mcp --root <folder>`. The root is the folder the agent works
in: meshes it grooms on, and every `.groom`, `.abc`, `.usda` and `.png` it writes. Without
`--root`, the server uses the folder it was started in. Make a folder for it, for example
`Documents\grooms`.

## Connect your AI app

Each app has its own config file. In the snippets below, replace the paths with your own. In JSON,
backslashes are written twice.

### Claude Desktop

Open **Settings > Developer > Edit Config**, add GroomLab to `claude_desktop_config.json`, then
restart Claude Desktop:

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "groomlab": {
      "command": "C:\\Users\\you\\Documents\\GroomLab\\GroomLab\\bin\\groomlab-cli.exe",
      "args": ["mcp", "--root", "C:\\Users\\you\\Documents\\grooms"]
    }
  }
}
```

### Claude Code

Run this once, in a terminal:

```bash
claude mcp add --scope user groomlab -- "C:\Users\you\Documents\GroomLab\GroomLab\bin\groomlab-cli.exe" mcp --root "C:\Users\you\Documents\grooms"
```

`/mcp` in Claude Code shows whether it is connected. Leave out `--root` to work in the folder
Claude Code was started in.

### Cursor

Add the server to `~/.cursor/mcp.json` (every project) or `.cursor/mcp.json` (one project):

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "groomlab": {
      "command": "C:\\Users\\you\\Documents\\GroomLab\\GroomLab\\bin\\groomlab-cli.exe",
      "args": ["mcp", "--root", "C:\\Users\\you\\Documents\\grooms"]
    }
  }
}
```

### VS Code

Add it to `.vscode/mcp.json` in your workspace (or run **MCP: Add Server** from the command
palette), then use it from Copilot's agent mode:

```json title=".vscode/mcp.json"
{
  "servers": {
    "groomlab": {
      "type": "stdio",
      "command": "C:\\Users\\you\\Documents\\GroomLab\\GroomLab\\bin\\groomlab-cli.exe",
      "args": ["mcp", "--root", "${workspaceFolder}"]
    }
  }
}
```

Any other app that supports MCP servers over stdio works the same way: the command is
`groomlab-cli`, and the arguments are `mcp --root <folder>`.

## Live: the groom open in Maya, the app or Blender

With **Agent Link** on, the agent works on the grooms you have open, as you watch: in Maya the
scene's grooms, in the app the open groom, in Blender the scene's grooms. Every change it makes is
one step of that program's undo, and you can take it back with Ctrl+Z like your own.

1. Turn on **... > Agent Link** in the Groom Tools (in Blender, in the GroomLab window or the
   sidebar's GroomLab tab). It is off by default and stays off until you turn it on in each
   session.
2. Start the MCP server with `--live`, for example in Claude Code:

   ```bash
   claude mcp add --scope user groomlab-live -- "C:\Users\you\Documents\GroomLab\GroomLab\bin\groomlab-cli.exe" mcp --live
   ```

   or `"args": ["mcp", "--live"]` in Claude Desktop's config. `--live maya`, `--live app` or
   `--live blender` picks one when several GroomLab programs run their link; without a name the
   server takes the newest.

While an agent is connected, the Groom Tools' header shows an **Agent** badge with a stop button;
stopping disconnects it. The tools work on the current groom unless the agent names another, and a
few leave their work to the program's own menus (making a groom, exporting curves). In each program:

- **Maya**: each tool call is one undo step named `Agent: <tool>`; the agent's `undo`, `redo` and
  `history` are Maya's undo queue. Files are read and written in the Maya project's folder, and
  `render_preview` with `viewport: true` shows the viewport as you see it. The photos the agent adds
  and lines up are reference cameras in the scene, the same ones the Photos window shows, so they
  are saved with the scene. `render_frame` renders with Arnold, Hardware 2.0 (with Maya's window
  open), V-Ray Standalone or RenderMan, if installed.
- **The app**: each change is one step of Edit > Undo, the same history as yours, so the agent's
  `undo` takes back your last step too. Files are read and written in the open groom's folder
  (`Documents\GroomLab` for an unsaved one); `render_preview` with `viewport: true` shows the
  viewport, and `render_frame` renders the app's lookdev view.
- **Blender**: each change is one step of the groom's GroomLab history (Ctrl+Z in the Groom Tools)
  and one Blender undo step named `Agent: <tool>`, so Edit > Undo takes it back as it takes back a
  stroke. Files are read and written in the `.blend`'s folder (`Documents\GroomLab` while it is
  unsaved). Photos the agent adds become cameras of the scene. `render_frame` renders with Cycles or
  EEVEE.

With no program running its link, `--live` works on grooms of its own and says so. The link listens
on 127.0.0.1 only, and every request carries a token from a file in `Documents\GroomLab\agent_link`
that only your user can read; the file goes away when the link stops or the program quits.

## The tools

The agent sees these tools, each with a description and a JSON Schema for its arguments. Grooms
are held in memory by name, so one session can work on several grooms. Each tool that changes a
groom answers with a short summary: strand and point counts, guides, bounds, and any node's errors.

| Tool | What it does |
| --- | --- |
| `list_nodes`, `describe_node` | The node catalog by category, and one node type's inputs and params (kind, default, range, unit, what it does). Includes your library's compound and script nodes. |
| `list_presets`, `list_sample_meshes` | The shipped presets (complete looks) and sample meshes (Nika, Manny, a wolf). |
| `get_docs` | Any page of these docs as text, by name or by a few words, so the agent can read how a feature works. |
| `new_groom`, `open_groom`, `list_grooms` | A new groom on a sample or an `.obj`/`.abc` mesh (the default graph or a preset), or a `.groom` file opened. On a whole head (face and neck in the mesh) the answer says so; `scalp: "from_landmarks"` keeps the hair above the hairline the face's landmarks give. |
| `scalp_from_landmarks` | On a whole head: Scatter's density map painted 1 above a hairline through the forehead, the temples, over the ears and down to the nape, 0 on the face, ears and neck. With photos lined up, the hairline moves to where their hair masks meet the face (`photoPoints`: how many of the head's points they set). Heuristic: check it with `render_preview` or `compare_to_photo`. |
| `apply_preset` | Replaces the graph with a preset's, or inserts its look as one compound node. |
| `get_graph`, `add_node`, `remove_node`, `connect`, `disconnect`, `set_params` | Reading and editing the node graph. `add_node` with `after` inserts a node into the chain; `set_params` checks values against the param's kind, range and choices. |
| `sample_scalp`, `add_guides`, `get_guides`, `set_tube` | Guide curves: points spread over the scalp, guides from point lists or grown from a root (length, droop), and their tubes (shape, width, aspect, twist) for tube locks. |
| `add_script_node`, `save_node` | A [script node](/docs/custom-nodes#script-nodes) written from text. Errors come back with their line and column, and nothing changes until the script is valid. Saves script and compound nodes as `.glnode` files. |
| `scalp_landmarks` | Named places on the scalp (top, crown, front hairline, nape, back, temples, ear sides) with the surface's normal, and the groom's directions (up, front, the character's left...). Approximate; strokes, painting and selection take the names as points. |
| `brush_stroke` | One of the brushes run along a path, as an artist's stroke: comb, smooth, straighten, lift, length, cut, twist, attract, slide, erase, shape, clump, paint, freeze / unfreeze, place, draw, part, flow. The path is world points, or `from` / `via` / `to` (landmarks or points) along the scalp's surface; radius, strength, level or group, symmetry. The answer says what changed: guides touched, added and removed, how far points moved, lengths before and after. |
| `select_guides`, `guide_op` | A selection by ids, a sphere around a point or landmark, a group or a level; and the Edit Guides menu's operations on it (delete, lock, freeze, mirror, move or duplicate to a group, resample...), Generate Children and tube edits. |
| `paint_map` | A scalp map made, filled and painted along a path, for example density (`"for": "scatter.density"`: the map linked to the param, 0 where no hair grows) or a clump mask. |
| `undo`, `redo`, `history` | Steps back and forward through a groom's changes (64 kept), and the list of them. Each tool call is one step. |
| `add_photo`, `photo_view`, `mesh_landmarks`, `align_photo`, `photo_edit`, `guides_from_photos` | Reference photos, as the Reference window works with them: a photo added and shown under a pixel grid labelled in its own pixels (`region`: a part of it enlarged under a 5 or 10 pixel grid, to read pixels exactly), the mesh drawn from a side with numbered points and their 3D positions, the camera lined up from pairs of a photo pixel and a mesh point (the error in pixels and the mesh drawn over the photo), flow arrows and mask touch-ups, and guides grown from the lined-up photos with the look they suggest (`apply_look` sets it) and the sides of the scalp no photo sees. |
| `compare_to_photo` | The groom against each lined-up photo (or the one named): its hair's silhouette through the photo's camera against the photo's hair mask (IoU, the photo's hair it misses, its hair outside the photo's), how far the photo's hair reaches past the groom's round the head (top, left, right, lower; scene units), the hairline's offset where the hair from the top ends on the face, the hair's color (each's nearest melanin and redness), and the flow lock by lock (`flow.agreement`: the strands' directions against the photo's where both show hair, 1 alike, 0 unrelated; curls in step with the photo's raise it, an even frizz lowers it). A picture a photo: the hair the groom misses green, its hair outside the photo's magenta. Run it after `guides_from_photos` and after each change, to judge by numbers. |
| `guides_from_photos` on curly hair | Each guide follows a lock (`locks`: how many were traced in a photo and how many took their neighbours' curl, the mean radius and turn length): the curl the photo shows along it baked into its points. With `apply_look` each guide's strands clump onto it (Clump with the guides as its centers, its strength per lock from the guides' `lockStrength`, Interpolate keeping the guides' curls) and no Curl node goes over every strand. `locks: false` grows smooth guides and a Curl node instead. |
| Facial landmarks | On a whole head, `mesh_landmarks` also names the face's features it finds from the mesh's shape (`nose_tip`, `chin`, the eyes and their corners, the mouth's corners, the ears' tops and lobes, `hairline_middle`, `crown`, `nape`), each with a confidence. `align_photo` takes the names as points, so an earlobe is paired with the photo's earlobe. Heuristic: check the low-confidence ones on the picture. |
| `align_photos` | Several photos of one shoot lined up together: one focal length for all (leaning to a portrait lens when the pairs cannot tell it), each camera near its view's angle round the head, level, at about the same distance. Soft priors the pairs can overrule (`prior_weight`); each photo's error and angles, and the photos whose pairs fight the rest. Line up every photo this way, then morph. |
| `align_photo` options | A second solve with the shoot's priors (the view's angle, level, the focal and distance of the photos lined up already, `like`) is kept unless its pairs fit clearly worse, so a lone profile with a few pairs cannot tilt; `view` (front, back, left, right, top, `three_quarter_front_left`...: the side the photo shows) starts the solve there, which profiles and backs need; `refine` tightens the camera so the mesh's outline lies on the photo's where neither is hair (jaw, neck, ears), the pairs kept, before and after reported. 6 or more pairs solve the focal length when they can tell it; `focalSolved` says whether they did. |
| `morph_to_photos` | The scalp shaped so the lined-up photos' pairs land on their photo points (the mesh is another head than the photos'), always from the scalp before the first morph; `reset` puts that back. Each photo's pair error before and after, and the morphed outline over the photos. In Maya a blendShape on the scalp, in Blender a shape key, in the app a transfer onto the morphed scalp (which starts the app's history over: `reset` takes it back). |
| `root_tube`, `tube_levels`, `tube_shape` | The Tube tool's root-first tubes: a root drawn on the scalp (an outline, or a center and radius), duplicated, deleted, subdivided into cells by a density map; the tube hierarchy's levels and views; the tube shape library. |
| `check_expression` | An expression compiled as a param compiles it, what it reads, and its values over the strands (min, mean, max, a histogram), errors with their place. `set_params` takes `{"expression": ..., "min", "max"}`. |
| `import_animation`, `animate_scalp`, `simulate`, `sim_cache` | An animated scalp, guide cache and colliders from Alembic, or a head turn written from keyframes; a Simulate node added and stepped (the guides' stretch, tip motion and points under the scalp), and the frames baked to a cache. |
| `export_cards`, `export_game`, `stats` | Hair cards as glTF, or for Unreal or Unity (maps, hair cap, manifest, FBX); everything the last evaluation knows. |
| `measure_guides` | Numbers that describe the guides per group or for the selection: count, lengths, the mean root-to-tip direction (also in words), straightness, curl, how far they lean from the scalp. |
| `evaluate` | Counts, bounds, errors, notes and the slowest nodes' timings. |
| `render_preview` | A PNG of the groom that the agent can look at: the scalp shaded and the strands drawn in the hair's color, from the front, back, left, right, three-quarter or top view, several in a grid, or a turntable; in a look (studio, flat, rim, clay); through a camera or a lined-up photo's; the guides or tubes drawn over the hair, or two images, before and after the last change (`compare`). |
| `render_frame` | Live only: a frame from the program's own renderer (Arnold and others in Maya, the app's lookdev, Cycles or EEVEE in Blender), at the size and quality given (640x480, draft by default), returned as an image. |
| `save_groom`, `export` | A `.groom` file, or the strands as Alembic or USD curves over a frame range (as `groomlab-cli eval` writes them). |

<Callout type="info" title="The preview is not a render">
  `render_preview` is a simple CPU drawing (no GPU) for checking shape, length, direction and color:
  flat shading, one-pixel strands, no shadows. Grooms with more than 50,000 strands are thinned for
  it, and the response says so. For the real look, the agent can use `render_frame` while it is
  live in Maya, the app or Blender.
</Callout>

## An example session

> **You:** Make tube-lock anime hair on Nika and show me.

A typical agent does something like this:

1. `list_presets`, then `new_groom` with `{"name": "anime", "mesh": "nika", "preset": "tube_locks"}`.
   The summary has an error: Scatter's guide radius needs guides.
2. `sample_scalp` with `{"min_up": 0.3}` for points on the top of the head.
3. `add_guides` with roots from those points, for example
   `{"root": [0, 13, 0], "length": 18, "droop": 0.8}`, and a ribbon tube for all of them:
   `{"shape": "ribbon", "width": [1.6, 1.2, 0.2], "aspect": 0.35}`.
4. `render_preview` with `{"views": ["front", "side", "back", "three_quarter"]}`. The agent looks at
   the image and changes what it sees: `set_tube` for flatter locks, `set_params` on `clump`.
5. `save_groom` with `{"path": "anime.groom"}`, which you then open in Maya or the app to keep
   grooming with brushes.

To groom by hand, an agent places guides with `brush_stroke` (`{"mode": "place", "from": "front_hairline", "via": ["top", "crown"],
"to": "nape", "length": 14}`), combs them (`{"mode": "comb", "from": "crown", "to": "nape", "offset": 3}`), checks the result
with `measure_guides` and `render_preview` (`{"views": ["back", "left"], "guides": true}`), and paints density with
`paint_map`.

If a change goes wrong, the agent can call `undo`. If an argument is wrong, the tool's error says
why (a param's range, the node names it has, a path outside the folder), and the agent tries again.

## Groom recipes

Typical graphs, as the shipped presets build them. Lengths are in scene units (centimeters on
Nika, a head about 35 units tall). A preset applied to a scalp of another size is scaled to fit it.

- **Natural hair** (`hair_basics`): Scalp > Scatter (`density` 80, `length` 15) > Interpolate
  (with Guides) > Clump (`clumpBy` size, `size` 1.2, `strength` 0.8) > Noise (`amplitude` 0.05) >
  HairColor (`melanin` 0.7: 0 blond, 1 black; `redness`) > Width (`width` 0.007, tapered `profile`)
  > Resample (16 segments) > Output. Guides do most of the styling: without them, strands grow
  straight out along the scalp's normals.
- **Curly** (`curly`): as above, with Curl after Clump (`radius` 0.45, `frequency` 0.4,
  `coherence` clump, so each clump curls as one ringlet), and Resample at 40 segments for smooth
  curls.
- **Tube locks, anime and cartoon** (`tube_locks`): Scatter with `guideRadius` 1 (hair only on the
  guides' tubes, fed the guides), Interpolate with `fillTubes` on (strands fill each guide's tube to
  its tip; `tubeBlend` softens the edge), Clump with `followTubes`. The tubes' shape, width, aspect
  and twist (`set_tube`) set each lock's look.
- **Fur** (`creature_fur`): Scalp > Scatter (`density` 25, `length` 3.5) > Length (uneven ends) >
  Flow (fur lies along painted direction arrows; without arrows, along its own direction) > Clump
  (small tufts) > Noise > HairColor (`tipColor` and `tipStrength` lighten the tips) > Width > Resample
  (8 segments). Made at wolf size (100 units).
- **More looks:** `braids`, `wet`, `frizz`, `flyaways`, `gravity`, `two_tone_tips`, `parted_style`
  and the feather and scale presets. `list_presets` describes each one.

Key params by node: Scatter `density` (strands per square unit) and `length`; Clump `size` or
`count`, `strength` and `profile` (root to tip); Curl `radius` and `frequency`; Noise `amplitude`
and `frequency`; Length `fraction` and `randomness`; HairColor `melanin`, `redness`, `dye`
and the tip color; Width `width` and `profile`. `describe_node` gives every param with its range.

## Safety

- **One folder.** The server reads and writes only inside its root. Paths are resolved first, so
  `..` and links cannot leave it. This also applies to the files a groom names (caches, texture
  maps in params) and to `save_to`. GroomLab's own presets, nodes, sample meshes and docs are read
  where they are installed.
- **No network.** The server talks only to the app that started it, over stdin and stdout; with
  `--live`, to a GroomLab host on the same computer (127.0.0.1) whose Agent Link you turned on.
- **Limits.** Mesh files up to 512 MB, 5,000 guides per call, scripts up to 64 KB, previews up
  to 1024 pixels wide, exports up to 1,000 frames.
- **Nothing is overwritten by surprise.** Changes stay in memory until `save_groom`, `save_node` or
  `export` writes a file, and those writes go only to the paths the agent names, inside the root.
- **Same calls, same results.** Grooms evaluate deterministically, so the same calls give the same
  strands and the same preview pixels. Only timings differ between runs.

## Not yet

- **Faces from photos.** Facial landmarks are found on the mesh only; the photo's pixels are read by
  the agent (with `photo_view`'s zoom). Landmarks on stylized or very low-poly heads may be off: their
  confidence says so.
- **Renders without a host.** `render_frame` works only live. The server alone (`mcp --root`) draws
  `render_preview`'s CPU pictures only.
- **Painting maps.** A preset that reads painted maps (density, length) says which maps are missing.
  These maps can only be painted in GroomLab itself.
- **Flow arrows, parts and sculpts.** These come from the brushes in Maya, the app and Blender.
