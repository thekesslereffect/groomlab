<Callout type="info" title="Beta">
  The standalone app is in beta on Windows. It is usable, but details may change before the first
  release. Keep backups of important grooms, and report problems to
  [support@getgroomlab.com](mailto:support@getgroomlab.com) with the log file (see below).
</Callout>

The GroomLab app grooms, lights and exports grooms without Maya. It uses the same evaluation core
as the Maya plug-in, so a `.groom` file evaluates to the same strands in both.

## Quick start

Your first groom, from a head mesh to an exported file. [Install](#install) the app first.

<Steps>
<Step>

### Start a groom on a mesh

Choose **File > New Groom on Mesh...** (Ctrl+N), or **New groom on mesh** on the start card, and
pick the head as an `.obj` or `.abc` file (or try **GroomLab > Add Sample Mesh**). The groom starts
with the default graph and no guides, so it has no hair until you place some. (A `.groom` file from
Maya or Blender opens with **File > Open Groom...**, Ctrl+O.)

</Step>
<Step>

### Place guides

In **Groom Tools** on the left, pick **Place** (or **Place some guides** under **Your first
groom**) and click or drag on the scalp. Shape the guides with **Comb**. Hold **B** and drag to size
the brush, or hold **Y** and click for the [marking menu](#the-marking-menu). For more detail, open
**Guide Groups & Edits** and click **Generate children**.

</Step>
<Step>

### Pick a look

In the **Graph Editor** at the bottom, open **Presets**, pick a category and a preset and choose
**Apply**. The preset is fitted to your scalp and grows from your guides. For the hair color,
switch to **Look** mode (**View > Mode > Look**, Ctrl+2) and use the **Material** tab in
**Properties**.

</Step>
<Step>

### Tweak it in the graph

Click a node in the Graph Editor, for example the Clump, and drag its sliders in the settings
beside the graph; the groom updates as you drag. **Tab** over the graph adds a node.

</Step>
<Step>

### Save and export

**File > Save** (Ctrl+S) writes a `.groom` file that Maya and Blender open. **Export** mode
(Ctrl+4, or **File > Export**, Ctrl+E) writes Alembic, USD, an Unreal groom, Unity strands or glTF
cards; **GroomLab > Export** has the same targets.

</Step>
</Steps>

## Install

The app needs Windows 10 or 11 (64-bit) and a graphics card with Direct3D 11. There is no
installer:

1. [Download the GroomLab app](https://downloads.getgroomlab.com/app/GroomLab-App-windows-latest.zip)
   (also on the [Download](/download) page, with its SHA-256).
2. Unzip the whole folder anywhere you can write to, and run **GroomLab.exe** in it. Windows
   SmartScreen may warn about a new download: choose **More info**, then **Run anyway**.
3. It is free, with every feature and export enabled. **Help > Support GroomLab** opens the Ko-fi
   page.

**Help > Check for Updates...** reports a newer version. To update, download it, close GroomLab and
unzip it over the old folder; settings and recent files are kept. The log file for bug reports is
`%LOCALAPPDATA%\GroomLab\logs\GroomLab.log`. `README_BETA.txt` in the app folder repeats these
notes.

## Open a groom

With no groom open, the viewport shows **Open groom**, **New groom on mesh**, **Start from a
preset** and the recent files; the Graph Editor's menus and **Render** wait until a groom is open.
**Start from a preset** (or **Presets > Apply on a Mesh...**) asks for a mesh, makes the groom on
it and applies the look. After **New Groom on Mesh** the Groom Tools list the first steps (**Your
first groom**: place some guides, give it a look), ticked as you do them; the cross hides them for
good. **View > Tool Labels** turns the tool tiles' names off for compact icon tiles.

- **File > Open Groom...** (Ctrl+O) opens a `.groom` file, saved here or from Maya.
- **File > Open Recent** lists the last files opened or saved (a file that is gone is greyed out;
  **Remove Missing Files** and **Clear Recent Files** tidy the list).
- **File > New Groom on Mesh...** (Ctrl+N) starts a groom on an `.obj` or `.abc` mesh, with the
  default graph and no guides. An animated Alembic mesh becomes the groom's scalp cache, so the
  animation is kept. **GroomLab > Add Sample Mesh** starts one on a shipped head (Nika, Manny) or
  the wolf.
- Or drop a `.groom`, `.obj` or `.abc` file on the window.
- **File > Add Prop Mesh...** loads another mesh beside the groom (a body, clothes, a hat). Props
  are drawn and lit with the groom, and a ColliderMesh node can name one to keep the strands off
  it ([Colliders](/docs/utilities#colliders)).
- **File > Add Eye...** adds an eye: a prompt over the viewport takes its center, the direction it looks and its radius
  (prefilled in front of the scene), as `--eye` does on the command line.
- **File > Save Image...** saves the current view as a PNG.

**File > Reload from File** (Ctrl+R) reads the saved file again. When the groom has unsaved
changes, Reload, closing the window, **Quit** (Ctrl+Q), Open, New and a dropped or recent file ask
first in a prompt over the viewport: **Save**, **Discard** or **Cancel**. **GroomLab > Utilities >
Transfer Groom to Scalp...** moves the groom onto another mesh in the same two-view window as Maya's: pick a method,
then click marker pairs on both meshes or import them from a JSON file
([Utilities](/docs/utilities#transfer-to-a-new-scalp)). Open, New Groom on Mesh and Transfer show a
busy cursor and say what they are doing while they work. **GroomLab > Guides from Photos
(experimental)...** grows guides from reference photos ([Guides from photos](/docs/reference-photos#guides-from-photos-experimental)),
and **View > Turntable** turns the camera around the groom.

### Autosave

**File > Autosave** saves a groom with unsaved changes every 5 minutes (or 1, 10, 15 or 30; **Off**
turns it off) to a copy beside its file (`hair.groom~`; an untitled groom's goes in the settings
folder). Saving, discarding the changes or closing the window lets the copy go. If GroomLab closes
before that (a crash), the next start offers it in a prompt: **Recover** opens it in the file's
place with the changes unsaved, **Discard** deletes it, **Later** asks again next time.

## The layout

The window is laid out as Maya's: a menu bar, the viewport in the middle and docked panels around
it. There is no tool bar.

| Where | What |
| --- | --- |
| Top | The menu bar: **File**, **Edit**, **View**, **GroomLab** (the same menu as Maya's and Blender's GroomLab menu, in the same order) and **Help**. The window's title is the file's name; `*` means unsaved edits. |
| Left | **Groom Tools**: the brushes, guide groups, maps, correctives and photos. |
| Right | **Properties**: what the mode is about (the groom's settings, the look, the cards or the export). |
| Bottom | The **Graph Editor** with the selected node's settings beside it, and the timeline under it while the groom animates. |
| Viewport, top right | **Undo** and **Redo**. |
| Viewport, top left and bottom | The active tool's name, the strand count line (**GroomLab > Review > Strand Count HUD**) and messages. |

The modes **Groom**, **Look**, **Cards** and **Export** are in **View > Mode** (Ctrl+1 to Ctrl+4).
Groom mode shows the Groom Tools; the other modes hide them and give Properties their own panel.
Docks can be moved, tabbed together or floated; **View > Panels** shows or hides each one, and the
layout is kept for the next start.

A timeline appears at the bottom when the groom is animated (a scalp or guide cache, or a graph
that reads the time). It supports play, scrub and loop; **Follow** toggles
[follow-the-scalp](/docs/motion-and-simulation#follow-the-scalp). With a Simulate node in the
graph it also shows **Simulate**, **Bake** and **Clear** (also in **GroomLab > Simulate**); while it
runs, **Simulate** reads **Cancel** (the frames made stay in the cache).

## Groom Tools

The Groom Tools dock holds the same pieces as Maya's Groom Tools window, from the same shared
definitions. At the top: the groom's name with its eyes (the hair alone: the strands, instances
and cards go and come back at once while the guides stay; and the guides alone: every guide
group; **View > Guides On/Off** and **Alt+Shift+G** too), the Graph Editor and more buttons,
the guide **Group** the brushes work on (**Isolate** shows only it and its child groups at full color) and
**Symmetry**. Then four tabs:

- **Tools**: every tool as a tile (Create, Shape, Trim and Paint brushes, then **Select**,
  **Freeze** and **Unfreeze All**), the active tool's settings card, and the sections **Tubes**
  (with Place, Draw, Shape and Select), **While Sculpting** (with the brushes that stroke),
  **Guide Groups & Edits** and **Output** (Simulate Range, Export, Render, Studio, Transfer and
  Import).
- **Paint**: the painted maps (vertex maps, textures, guide layers) with their bar and right-click
  menu ([Painting maps](#painting-maps)).
- **Correctives**: shot-sculpt layers ([Correctives](#correctives)).
- **Photos**: reference photos to groom to ([Photos](#photos)).

## Groom with brushes

Pick a tool tile in **Groom Tools**. The tiles hold the same brushes as Maya, in the same order:
Create, Shape, Trim and Paint, then **Select** and **Freeze**. See
[Guides and brushes](/docs/guides-and-brushes) for what each does.

- Drag on the groom to stroke. **Shift** smooths; a negative strength reverses a brush that works both ways.
- **Freeze** paints a per-guide freeze mask; other brushes skip frozen guides, which draw blue.
  **Ctrl** unfreezes; **Unfreeze All** clears the mask.
- **Ctrl+drag** paints guides into the selection (all other guides freeze), **Ctrl+Shift+drag**
  lassos them; **Ctrl+click** adds the guides inside the brush ring, and where it holds none
  deselects and unfreezes all; **Ctrl+Shift+click** toggles them (a selected guide comes out and freezes). (Painting maps, Ctrl does the opposite.) **Page Up** and **Page Down** step the level. **Solo new
  guides** on the Place card solos guides as you place them; Select mode solos the selection.
- Hold **B** and drag, or middle-drag, to set the radius. Hold **M** and drag, or
  **Shift+middle-drag**, to set the strength.
- **Alt+Shift+X** turns symmetry on or off.
- Hold **Y** and click for the marking menu.
- **Alt** with any mouse button moves the camera, whatever the tool.
- **Esc** leaves the brush for the camera.

The active tool's card holds its settings in Maya's order: radius, strength, falloff and its curve,
the strength along the guide, pen pressure and the tool's own settings.

**Guide Groups & Edits** lists the guide groups. Untick a group to hide it; double-click to rename
it; right-click for its menu. Its bar adds a root or child group, generates children, selects,
removes, reparents, promotes or demotes a group, deletes the selected guides, mirrors a group
+X → -X, syncs symmetry and resamples guides. Part lines drawn with the Part brush are listed on its
card. See [Guide groups](/docs/guides-and-brushes#guide-groups).

### Tubes

The **Tubes** section sets the cross-section the guides' tubes have: the shape (round, flat, your
own drawn in the outline editor and kept in the groom's library), **Width**, **Flatness** and
**Twist** for the selected or soloed guides and for the guides Place and Draw make, **Smooth**,
**Fill Tubes** and **Tube Blend**. Width shows in the length unit picked in the Graph Editor's
**Edit > Units**. The Shape brush paints width, flatness or twist along a guide.

### The marking menu

Hold **Y** and press the left mouse button over the viewport: the marking menu opens around the
cursor, as Maya's GroomLab marking menu does. Comb, Slide, Smooth, Cut, Place, Draw, Length and Lift
sit at the compass points; the rest of the brushes are listed below them, then **Select**,
**Freeze** and **Groom Tools**.

- Drag toward an item and let go to pick it. A compass item is picked by direction alone, so a
  short flick is enough.
- Let go without moving and the menu stays open: click an item. Click in the middle, or press
  **Esc**, to close it.

## The Graph Editor

The Graph Editor is docked at the bottom, with the selected node's settings at its right (as in
Maya). **GroomLab > Graph Editor** (or **Tab**) shows it and puts the focus on it. Its bar has
**Add Node**, **Presets** and **Edit** menus and a status line.

- **Tab** over the graph searches for a node to add, by name, by what it does (symmetry finds
  Mirror, frizz finds Noise) or by category. **Enter** adds it, wired after the selected node when
  their ports match. **Add Node** lists the nodes by category, and new script nodes, imported
  nodes and the nodes folder.
- Drag from an output port to an input to wire them. Drag a wire off an input to disconnect it.
  Dropping a node on a wire inserts it there.
- Click a node to select it; its params show beside the graph. **Ctrl+click**
  toggles a node in the selection, **Shift+click** adds one, and dragging on empty space selects
  in a box; dragging a selected node moves them all. **Delete** and **B** act on the whole
  selection; **Ctrl+C** / **Ctrl+V** copy and paste the selected nodes with the links between them.
- **V** (**View Up to Here**) shows the groom up to the selected node instead of the output's
  (the node says VIEWING; **V** again goes back). Exports and renders still use the output.
- A node that fails to evaluate gets a red ring and a **!** badge; its error is in its tooltip and
  under the title in its settings.
- Dragging a link over a port it can't feed says why; dropping it there changes nothing.
- **Ctrl+G** groups the selected nodes into one **Compound** node, as in Maya's Graph Editor: the
  links from outside become its inputs, and one of the nodes must feed the rest of the graph.
  Double-click a Compound (or select it and press **Ctrl+Shift+G**) to open it: its nodes go back
  into the graph where they were. **Ctrl+Z** undoes either in one step.
- **Backdrops** frame part of the graph: right-click a node > **Add Backdrop Around Selection**, or
  right-click the canvas > **Add Backdrop**, and type its title. Drag its title bar to move it with
  the nodes on it, drag its corner to resize it, double-click the title to rename it, right-click it
  for **Color** and **Delete Backdrop** (or select it and press **Delete**).
- **Pins** tidy the wires, as in Maya's Graph Editor (Unreal's reroute nodes): double-click a wire
  for a pin, drag it to route the wire, drop it on another pin of the same output to bundle them,
  drag from its right side for another wire of its signal, drop a wire from an output on it to
  feed all its wires from there; **Delete** removes a selected pin. **Snap** on the Graph Editor's
  bar puts nodes and pins on the grid as you drag them.
- Right-click a node for Maya's node menu: rename, duplicate, bypass, delete, set as the output,
  bake, upgrade and more. Right-click the canvas to add a node or a backdrop, tidy the layout or
  frame the graph.
- Middle-drag pans; scroll to zoom. **F** frames the selected node (none: the whole graph),
  **A** the whole graph. Alt+drag moves the camera. **Esc** gives the keys back to the viewport.

The **Edit** menu has undo and redo, framing, **Tidy Layout** (Ctrl+L), grouping, copy and paste,
**Units** (show lengths, widths and densities in centimeters, millimeters, micrometers, inches or
scene units), the theme, **GPU Preview** and **Reload from Groom**. Each edit is one undo step. See
[Node graph](/docs/node-graph) for the nodes.

### Presets

The Graph Editor's **Presets** menu (or **View > Graph Presets**) lists the presets by category;
hover one for its description. Each preset has two actions:

- **Apply** replaces the graph with the preset.
- **Insert after selected node** keeps your graph and adds the preset's look as one Compound
  node after the selected node, or before the output when nothing is selected.

In both cases the preset's lengths and densities are scaled to your scalp, any maps it reads are
created, and the change is one undo step. The same menu has **Save as Preset...**, **Copy Graph**
and **Paste Graph** (the graph as JSON text, to share or paste onto another groom). See
[Presets](/docs/presets).

### Parameters

Click a node in the graph (or in **Node List**, from **View > Panels**) to edit it.

- Params are grouped under collapsible headers. Rarely used params are in **Advanced**, collapsed.
- A param is hidden while the node's other settings make it inactive.
- Numbers show their unit (percentage, degrees, turns, seconds or pixels; lengths, widths and
  densities as **Edit > Units** picks).
- Ramps have a curve editor. Mappable params can take a constant, a painted map, a texture, a
  color set, an expression or a field. Right-click a param for its menu (paint it, link it, expose
  it as an input, **Drive with Slider**).
- **Bypass** passes the node's input through unchanged.
- **Upgrade** appears beside the title when the node was saved with an older version of its
  operator. It switches the node to the newest behaviour, as one undo step.

Dragging a slider updates the groom during the drag. With **GPU Preview** on, the GPU evaluates the
preview during the drag and the CPU evaluation runs on release.

## Painting maps

Open the **Paint** tab in Groom Tools. **+ New Map** creates a vertex map, a texture map or a guide
layer, grayscale or color. Pick a map and click **Paint this map**; the brush paints toward the set
value or color, **Ctrl** toward 0 on a grayscale map (toward 1 when the value is 0) and toward the
inverse color on a color map. **Show on scalp** displays the map on the scalp. **Import...** brings
an image in as a map; right-click a map to rename, convert or delete it, make it color or gray, or
relink or reload a texture map's image.

To paint a setting, choose **+ New Map > for a setting** (**Density**, **Width**, **Length**,
**Clump strength**, **Curl**, **Noise amplitude**, **Flyaways**, or any mappable param of the
graph), pick vertex or texture map, and create it: a white map is created, connected to the
setting, selected and painted with the paint brush, in one undo step (if the setting already reads
a map, that map is selected instead). Strokes paint toward the value (1: the setting's full value);
**Ctrl** paints toward 0, so Ctrl on the density map removes hair. A mappable param's **Paint**
pill does the same for that param. See [Painting maps](/docs/painting-maps).

## Correctives

The **Correctives** tab holds shot-sculpt layers applied over the animated groom. A **New layer**
applies on every frame; **Fix this frame** creates a layer at full weight on the current frame that
fades in and out over six frames. Pick a layer under **Sculpt into** to send brush strokes to it
instead of the guides. Right-click a layer to solo it or key its weight.

## Photos

The **Photos** tab holds reference photos to groom to, each with its own camera. Double-click a
photo (or **Look Through**) to see the groom through its camera with the photo in the frame;
**Lock** keeps the camera there. **Opacity**, in front or behind and the eye set how the photo
shows; **Focal Length** sets the camera's lens. **Align Photo...** opens the Photos window on the
picked photo: the photo and the mesh side by side, point pairs clicked on each, the camera lined up
as you go. **Guides from Photos** opens the same window's Guides stage
([Reference photos](/docs/reference-photos)).

## Properties

The **Properties** dock follows the mode:

- **Groom** mode: the groom's settings in the order of Maya's Attribute Editor: **Groom** (preview
  density, point budget), **Inputs** (the scalp, rest and guides, the collider, the file),
  **Controls**, **Hair Color**, **Display** (guides, strand shading), **Sculpting**, **Game Cards** and
  **Rendering**. The point budget is 0 (no limit) by default; set one to keep very large grooms
  interactive (past it the preview thins itself).
- **Look** mode: the look card ([Look](#look)).
- **Cards** mode: the cards panel ([Game cards](#game-cards)).

### Scalp Subdivision

**Inputs > Scalp Subdivision** (**Off**, **1**, **2**, **3**) smooths a low-poly scalp with
Catmull-Clark subdivision, as Maya's smooth mesh preview (the 3 key) or Arnold's subdivision does.
The hair grows on the smoothed surface, and the viewport draws that surface instead of the mesh
itself. Brushes, **Place** and **Draw**, part and flow strokes, map painting, and the picks in
**Transfer** and **Guides from Photos** all land on the smoothed surface.

- Each level makes four times the triangles. The count beside the setting shows how many the hair
  grows on; it turns to the warning color past 2 million, where brushes and the viewport slow down.
- Painted vertex maps stay on the mesh's own vertices and blend smoothly across the smoothed
  surface, as in Maya.
- The **Scalp** node's default (**Match Render**) follows this setting. A Scalp node set to a level
  of its own wins; the count then says so.
- One undo step. Saved in the `.groom` file as the scalp's subdivision level: a groom saved from
  Maya with a smoothed scalp opens at its level.
- **Export** mode: the export panel ([Export](#export)).

## Look

**Look** mode (Ctrl+2) shows the look card in Properties, with three tabs:

- **Material:** hair color swatches (the groom's own, black, brown, blonde, red, white, dyed),
  HairColor's two ways (**Natural**: **Melanin** and **Redness**; **Picked color**: a **Color**),
  **Roughness**, **Tip color** and **Tip strength**, **Hue random** and **Saturation random**.
  These edit the groom's HairColor node, so they are saved with the groom. **More settings** shows every hair material setting and the other surfaces
  (scalp, props, eyes).
- **Lighting:** presets (studio, daylight, overcast, sunset, rim), exposure, the lights, an
  environment, the tone map and the background. **GroomLab > Studio** applies the same presets.
- **Render:** interactive or refine quality, refine samples and resolution scale.

With refine quality the viewport accumulates samples until it converges; **File > Save Image...**
then saves the view as a PNG. **All settings** opens **Look Settings** (every look setting,
including texture files).

## Render in V-Ray

With **V-Ray Standalone** installed (V-Ray 7 tested), **GroomLab > Render > Render Frame in V-Ray** renders the
groom at this frame as the viewport shows it: every strand (not the preview density), the
viewport's camera, the lighting preset's lights and environment, the background, the exposure and
the scalp. **GroomLab > Render > Render Turntable in V-Ray** renders 36 frames with the camera going once
around the groom. A window shows the progress and the image as it comes; **Cancel** stops V-Ray,
**Save Image...** saves the image and **Show in Folder** opens the folder with the images and the
scene files.

- The hair is GroomLab's V-Ray hair, as the **V-Ray scene** export writes it: each strand's color
  and a VRayHairNextMtl shader set up from the groom's look ([Other renderers](/docs/other-renderers#v-ray)).
  The look panel's swatches render when they are the groom's own HairColor settings; an override
  material that only the viewport uses does not.
- The image is V-Ray's linear result saved as an sRGB PNG, without the viewport's tone map: compare
  it with the viewport set to **Tone map: None**.
- Props and eyes, shadow softness and ambient occlusion stay in the viewport.
- The app looks for `vray.exe` in the `GROOMLAB_VRAY` environment variable, then the one picked with
  **GroomLab > Render > V-Ray Standalone Location...**, then V-Ray's default install folder
  (`C:\Program Files\Chaos\V-Ray\Standalone for x64\bin`) and the `PATH`.
- V-Ray runs as its own process, so the app stays usable while it renders.
- From a script: `GroomLab hair.groom --render-vray frame.png --size 1920x1080` renders without a
  window and quits (`--vray-turntable 36` for a turntable: `frame.0001.png` and on).

## Render in RenderMan

With **RenderMan Pro Server** installed (RenderMan 27.3 tested; free for non-commercial use),
**GroomLab > Render > Render Frame in RenderMan** and **Render Turntable in RenderMan** render the
same way in RenderMan's `prman`, in the same window: the groom as it is now is written to a
`.groom` file that GroomLab's RenderMan procedural (in the app's `procedurals/renderman` folder)
evaluates at render time, every strand, shaded by PxrHairColor and PxrMarschnerHair set up from the
groom's look ([RenderMan](/docs/other-renderers#renderman)); the viewport's camera, the lighting
preset's lights (PxrDistantLight) and environment (PxrDomeLight), the background, the exposure and
the scalp go to a RIB beside it.

- The image is prman's linear result saved as an sRGB PNG, without the viewport's tone map.
- Under a strong key light, light hair renders a little darker than in the viewport and V-Ray.
- The app looks for `prman` in the `GROOMLAB_PRMAN` environment variable, then the one picked with
  **GroomLab > Render > RenderMan Location...**, then `RMANTREE`, RenderMan's default install folder
  (`C:\Program Files\Pixar\RenderManProServer-*\bin`) and the `PATH`.
- From a script: `GroomLab hair.groom --render-prman frame.png --size 1920x1080` renders without a
  window and quits (`--prman-turntable 36` for a turntable).

## Game cards

**Cards** mode (Ctrl+3) generates hair cards from the groom; its panel is in Properties. Click **Add Cards node** if the graph has
none.

- **Strands** or **Cards** switches what the viewport shows. **Maps** shows the baked maps on the
  cards, alpha-tested by coverage as in Maya and in a game engine. Before a bake the cards are
  untextured.
- **LOD** picks **Hero**, **Mid**, **Low** or **Custom**. Sliders set cards per clump,
  layers, width, segments, variations, the atlas size and a card budget.
- **Bake maps** writes the cards' maps (depth, coverage, tangent, attribute, color, occlusion) as
  TGA files in a `_cards` folder beside the saved groom file, with a busy cursor while it bakes. The
  baked atlas shows in the panel.

The panel shows card, triangle and texture counts, and indicates when the cards have changed since
the last bake. See [Game export](/docs/game-export).

## Export

**Export** mode (Ctrl+4, or **File > Export**, Ctrl+E) writes the groom to other formats. Pick a target:

| Target | What you get |
| --- | --- |
| **Alembic curves** | Every strand with its ID, attributes, color and root UV ([Strand attributes](/docs/rendering#strand-attributes)). |
| **USD curves** | BasisCurves in a text `.usda` layer. |
| **Unreal groom** | Alembic for Unreal's groom importer, with the guides it simulates. |
| **Cards (glTF)** | The cards at this frame as `.glb` (or `.gltf`), maps inside, with the hair cap. |
| **Unity strands** | Alembic for Unity's hair package, resampled to a fixed point count. |
| **Card maps** | The cards' texture maps as a preset packs them (Unreal, Unity HDRP, every map on its own, your own), TGA, PNG, TIFF or EXR up to 8K; the output is a folder and a name ([Export card maps](/docs/game-export#export-card-maps)). |
| **V-Ray scene** | The strands and their V-Ray hair shader as a `.vrscene` for V-Ray Standalone or V-Ray for Maya ([V-Ray](/docs/other-renderers#v-ray)). |

Set the frames (the current frame, or a range for an animated groom), the density and the target's
options, then the output file (type a path or pick it with **...**). **Export** shows progress and
can be cancelled. The same targets are in **GroomLab > Export** (and the Output section's **Export**), with
**Scales Instancer (USD)...**. The FBX exports are only available in Maya and Blender.

## Save and open in Maya

**File > Save** (Ctrl+S) and **File > Save As...** (Ctrl+Shift+S) write a `.groom` file: the graph,
guides, scalp, maps, parts, flow and correctives. Export mode has **Save** and **Save as...** too.

In Maya, choose **GroomLab > Groom Files > Import Groom File...**. Select the scalp mesh first if
the scene has it; otherwise GroomLab creates the scalp from the file. To pull later edits into a
groom linked to the file, save in the app, then choose **GroomLab > Groom Files > Reload from
Groom File** in Maya (one undo step). See [The .groom format](/docs/groom-format).

## Not in the app yet

These are in Maya but not in the app. Grooms that use them still open and evaluate in the app as
made.

- **Import:** **From XGen...** and **From Yeti...** ([Importing](/docs/importing)). Alembic curves
  come in through **GroomLab > Import > Alembic Curves...** (an **ImportCurves** node).
- **Rendering:** Arnold and Redshift, and Maya's **Render Turntable...** (the app renders RenderMan
  and V-Ray frames and turntables: [Render in RenderMan](#render-in-renderman),
  [Render in V-Ray](#render-in-v-ray)). The app's viewport refines; export Alembic or USD for other
  renderers.
- **Exports:** the FBX ones (**Unreal Cards...**, **Unity Cards...**, **Unity Feathers...** and
  **Scales Mesh (FBX)...**). The app bakes the card maps and writes glTF cards.
- **Graph Editor:** a param's **Paint > On Guides** (a setting painted on the guides as a guide
  layer; the app paints settings as vertex or texture maps), and keys on params (**Set Key**,
  **Delete Key**).
- **Animation:** Maya's nHair (**Simulate > Legacy**). The app plays a groom file's caches and runs
  the Simulate node.
- More than one groom in a window, and so **Copy Graph to Other Grooms...** (in the app, **Copy
  Graph** and **Paste Graph** under Presets carry a look between grooms).

## Themes

**GroomLab > Theme** (also in the Graph Editor's **Edit** menu) picks the app's colors from the
same themes as Maya: **Charcoal** (the default: solid neutral grey panels with thin borders, an
off-white primary button, muted color only where it means something), **Playful** (translucent
panels, bright primaries), **Polar** and **Studio**. The window restyles at once, and the choice is
kept for the next start. A scripted run takes `--theme charcoal` (or another name) for that run
alone.

Your own themes are JSON files in your themes folder (the same one as Maya's,
`Documents\maya\groomlab\themes`; the `GROOMLAB_USER_THEMES` environment variable names another)
and in the folders listed in `GROOMLAB_THEME_PATH`. **New Theme from Current...** writes a copy of
the current theme there to edit, **Reload Theme** reads the files again after an edit, and **Open
Themes Folder** opens the folder. See [Themes](/docs/utilities#themes) for the file format.

## Settings

The app keeps its settings (recent files, the theme, autosave, units, the panels' layout) in
`%APPDATA%\GroomLab\GroomLab.ini`. A scripted run (`--ui-screenshot`, `--screenshot`, the exports,
`--render-vray`, the benchmarks) never reads or writes them: it uses a throwaway folder, or the
folder `GROOMLAB_SETTINGS_DIR` names.
